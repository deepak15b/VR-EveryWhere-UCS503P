# 🚀 Week 3: System Architecture Design & Frontend Project Planning

**📅 Date:** August 28 – September 3, 2026  
**🎯 Core Task:** Designed the overall system architecture diagram, established the frontend application routing structure, and created the initial wireframes for key UI screens.

---

### 🛠️ Key Contributions & Decisions

- **🏗️ System Architecture Diagram:** Created the full system architecture diagram showing the interaction between all system components:
  - React Frontend (browser-based SPA)
  - Three.js VR Viewer (embedded within React)
  - Spring Boot Backend (REST API)
  - PostgreSQL Database
  - Unity VR Client (optional native headset client)
  - External: Google Maps API, Wikimedia 360° panoramas

- **🗺️ Application Route Structure:** Planned and documented the React Router route structure:
  - `/` — Home Page
  - `/explore` — Destination Browse & Search Page
  - `/destination/:id` — Destination Detail Page
  - `/tour/:id` — VR Tour Page (protected)
  - `/favorites` — User Favorites Page (protected)
  - `/profile` — User Profile Page (protected)
  - `/login` — Login / Register Page

- **🖼️ UI Wireframes:** Created low-fidelity wireframes for the five core screens:
  - Home Page hero section with featured destinations
  - Explore Page grid with category filter and search
  - Destination Detail Page with VR tour launch button
  - VR Tour Page with 360° viewer and control overlays
  - Favorites Page with saved destination cards

- **📋 Requirements Specification:** Drafted the functional requirements document listing all features agreed by the team, categorized as Must Have, Should Have, and Could Have using MoSCoW prioritization.

- **🤝 Task Allocation:** Coordinated with Abhishek (VR/Unity) and Deepak (Backend) to finalise task ownership for the development sprints starting in Week 4.

---

### 📚 Learning Outcomes

- Learned how to create a system architecture diagram that accurately represents the relationships between frontend, backend, database, and external components.
- Understood how React Router enables a single-page application to support multiple views through URL-based routing.
- Gained experience applying MoSCoW prioritisation to manage the scope of a student software project.
- Learned the importance of agreeing on a clear routing structure before development begins to avoid integration conflicts.
